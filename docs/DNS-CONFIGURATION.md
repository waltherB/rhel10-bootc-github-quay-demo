# DNS Configuration

All RHEL 10 bootc images built by this project are configured with persistent DNS settings to use **Cloudflare (1.1.1.1)** and **Google (8.8.8.8)** DNS servers.

---

## Overview

DNS configuration is critical for bootc images to ensure reliable network connectivity. This project uses a **multi-layer approach** for DNS persistence across RHEL 10 bootc deployments.

---

## DNS Configuration Layers

### Layer 1: systemd-resolved Configuration
**File:** `/etc/systemd/resolved.conf.d/99-dns.conf`

```ini
[Resolve]
DNS=1.1.1.1 8.8.8.8
FallbackDNS=1.1.1.1 8.8.8.8
DNSSECNegativeTrustAnchors=
```

**Purpose:** Primary DNS resolver configuration at the systemd level. This ensures DNS resolution works even if NetworkManager is not running.

**Persistence:** Permanent (survives reboots, image updates)

### Layer 2: NetworkManager Configuration
**File:** `/etc/NetworkManager/conf.d/99-dns.conf`

```ini
[main]
dns=systemd-resolved
dhcp=dhclient
```

**Purpose:** Configures NetworkManager to delegate DNS resolution to systemd-resolved, ensuring consistency across all network interfaces.

**Persistence:** Permanent (survives reboots, image updates)

### Layer 3: Fallback /etc/resolv.conf
**File:** `/etc/resolv.conf`

```
nameserver 1.1.1.1
nameserver 8.8.8.8
```

**Purpose:** Traditional fallback DNS configuration for systems without systemd-resolved.

**Persistence:** Semi-persistent (may be regenerated by NetworkManager on DHCP events, but systemd-resolved will continue to use Layer 1 & 2 configuration).

## DNS Servers

| Server | Provider | Address | Purpose |
|--------|----------|---------|---------|
| Cloudflare | Cloudflare Public DNS | 1.1.1.1 | Primary DNS |
| Google | Google Public DNS | 8.8.8.8 | Fallback DNS |

**Why these servers?**
- **Cloudflare (1.1.1.1):** Fast, privacy-focused, DNSSEC support, minimal logging
- **Google (8.8.8.8):** Globally distributed, highly reliable, widely recognized

## Verification

### Inside a Running Container

```bash
# Test DNS resolution
nslookup google.com
dig google.com
host google.com

# Check systemd-resolved status
resolvectl
systemd-resolve --status

# Check current DNS servers
cat /etc/resolv.conf
cat /etc/systemd/resolved.conf.d/99-dns.conf
cat /etc/NetworkManager/conf.d/99-dns.conf
```

### Inside a Running bootc VM

```bash
# SSH into the VM
ssh demo@<VM_IP>

# Verify DNS configuration
sudo resolvectl
sudo cat /etc/resolv.conf
sudo systemctl status systemd-resolved
```

### After bootc Upgrade

```bash
# DNS configuration persists across bootc upgrades
sudo bootc upgrade
sudo systemctl reboot

# After reboot, verify DNS is still configured
sudo resolvectl
nslookup google.com
```

## Buildtime Configuration

### In the Containerfile

DNS configuration is applied during the image build process:

```dockerfile
RUN mkdir -p /etc/NetworkManager/conf.d && \
    mkdir -p /etc/systemd/resolved.conf.d && \
    printf '%s\n' \
      '[main]' \
      'dns=systemd-resolved' \
      'dhcp=dhclient' > /etc/NetworkManager/conf.d/99-dns.conf && \
    printf '%s\n' \
      '[Resolve]' \
      'DNS=1.1.1.1 8.8.8.8' \
      'FallbackDNS=1.1.1.1 8.8.8.8' \
      'DNSSECNegativeTrustAnchors=' > /etc/systemd/resolved.conf.d/99-dns.conf && \
    printf '%s\n' \
      'nameserver 1.1.1.1' \
      'nameserver 8.8.8.8' > /etc/resolv.conf && \
    chmod 0644 /etc/resolv.conf
```

**Key Points:**
- Configuration is written at **image build time** (in the RUN instruction)
- All layers use `/etc/systemd/resolved.conf.d/` and `/etc/NetworkManager/conf.d/` (drop-in directories)
- Drop-in directories survive image updates and rollbacks

## Why This Matters for bootc

### Problem
Traditional mutable servers often have unpredictable DNS configuration, leading to:
- DNS resolution failures at boot time
- Inconsistent behavior across environments (dev, test, prod)
- Difficulty recovering from misconfiguration

### Solution
bootc images define DNS configuration as part of the immutable image definition:
- **Declarative:** DNS configuration is explicit in the Containerfile
- **Reproducible:** Every image built from the same Containerfile has identical DNS config
- **Traceable:** DNS settings are tracked in git alongside the image definition
- **Persistent:** DNS configuration survives reboots, updates, and rollbacks

## Customization

### Changing DNS Servers

To use different DNS servers, edit the Containerfile:

```dockerfile
RUN mkdir -p /etc/systemd/resolved.conf.d && \
    printf '%s\n' \
      '[Resolve]' \
      'DNS=8.8.8.8 1.1.1.1' \
      'FallbackDNS=9.9.9.9' > /etc/systemd/resolved.conf.d/99-dns.conf && \
    printf '%s\n' \
      'nameserver 8.8.8.8' \
      'nameserver 1.1.1.1' > /etc/resolv.conf
```

Then rebuild the image:

```bash
./scripts/local-build.sh
./scripts/local-push.sh
./scripts/local-sign-keyless.sh
```

## Troubleshooting

### DNS Not Resolving

1. **Check systemd-resolved is running:**
   ```bash
   sudo systemctl status systemd-resolved
   ```

2. **Check DNS configuration:**
   ```bash
   sudo resolvectl
   sudo cat /etc/systemd/resolved.conf.d/99-dns.conf
   ```

3. **Check NetworkManager configuration:**
   ```bash
   sudo nmcli con show
   sudo cat /etc/NetworkManager/conf.d/99-dns.conf
   ```

4. **Test DNS resolution manually:**
   ```bash
   sudo systemctl restart systemd-resolved
   nslookup google.com
   ```

### DNS Persists Across Rollback

If you rollback to a previous bootc image, DNS configuration will remain as it was in that image:

```bash
# Current DNS config
resolvectl

# Rollback
sudo bootc rollback --apply

# DNS config is from the previous image (1.1.1.1 and 8.8.8.8)
resolvectl
```

## Summary

All RHEL 10 bootc images built by this project include persistent DNS configuration using:
- **Primary:** Cloudflare (1.1.1.1)
- **Fallback:** Google (8.8.8.8)
- **Persistence Mechanism:** systemd-resolved + NetworkManager + /etc/resolv.conf
- **Traceability:** Configuration defined in Containerfile, tracked in git
- **Reliability:** Configuration survives reboots, upgrades, and rollbacks
